# 게임·이벤트 제작 UI 서버 연동 경계

## 웹 구현 상태

- `/admin/games`, `/admin/editor`는 `getAdminPortalAccess()`가 서버의 HttpOnly 세션을 검증하여 `SUPER` 또는 `USER_SERVICE_MANAGER`를 반환할 때만 콘텐츠를 렌더링한다.
- 현재 서버 인증·권한 계약은 미연동 상태이므로 두 경로는 보호 안내만 반환한다. 게임·이벤트·쿠폰·에디터 초안의 예시 데이터와 UI는 HTML/RSC에 포함되지 않는다.
- 브라우저 저장소, URL, 클라이언트에서 읽을 수 있는 쿠키, 임시 역할 플래그를 권한 판단에 사용하지 않는다.
- 서버 연동 전 게임/이벤트 생성·수정·발행 API 호출은 구현하지 않는다. 게임·이벤트 화면의 입력과 실행 버튼은 비활성 상태로 유지한다. 에디터는 로컬 초안 경험만 제공하며 저장·발행은 비활성이다.

## 서버에 필요한 권한 규칙

모든 API 요청은 서버 세션에서 역할을 추출하고 매 요청마다 확인한다.

| 작업 | 허용 역할 |
| --- | --- |
| 게임 목록/상세 조회, 게임 초안 생성·수정·발행 | `SUPER`, `USER_SERVICE_MANAGER` |
| 미션 에디터 초안 저장/불러오기/발행 | `SUPER`, `USER_SERVICE_MANAGER` |
| 이벤트 목록/상세 조회, 이벤트 생성·수정·발행 | `SUPER`, `USER_SERVICE_MANAGER` |
| 이벤트에 수량 제한 쿠폰 연결 | `SUPER`, `USER_SERVICE_MANAGER` |

`PARTNER_MANAGER`와 제휴업체 계정은 위 경로와 API에 대해 조회·변경 모두 불가해야 한다. 실패 시 서버는 401 또는 403을 반환하고, 웹은 콘텐츠를 표시하지 않는다.

## 제작 및 이벤트 데이터 계약

### 입력 DTO와 서버 응답 엔터티

- 생성 요청은 ID 없는 입력 DTO를 사용한다. 게임은 `CreateGameInput`, 이벤트는 `CreateEventInput`으로 구분하며, 입력 DTO는 목록이나 발행 대상이 될 수 없다.
- `POST` 생성과 `GET` 목록은 모두 서버가 발급한 안정적인 ID와 발행 상태를 가진 엔터티를 반환한다. 게임은 `id: GameId`, `publicationStatus: DRAFT | PUBLISHED`, 이벤트는 `id: EventId`, `publicationStatus: DRAFT | PUBLISHED | ENDED`를 반드시 포함한다.
- 이벤트 생성 입력의 `gameId`는 문자열을 새로 만들지 않고, 앞선 게임 생성/목록 응답의 `GameId`만 사용한다. 연결할 수량 제한 쿠폰도 서버가 허용한 목록에서 받은 `LimitedCouponId`만 사용한다.
- 발행 API는 ID 문자열이나 입력 DTO를 받지 않는다. `publishGame`은 목록/생성 응답에서 받은 `DraftGame`, `publishEvent`는 목록/생성 응답에서 받은 `DraftEvent`만 받으며, 발행 응답은 각각 `PublishedGame`, `PublishedEvent`를 반환한다. 서버도 대상 ID의 존재, ID 종류, 현재 `DRAFT` 상태를 재검증한다.
- ID는 응답 이후에도 변하지 않는 서버 식별자여야 하며, `createdAtKst`, `updatedAtKst`도 응답 엔터티에 포함한다. 클라이언트는 ID를 추측·합성·재활용하지 않는다.

### 게임

- 게임 제작 시 `minPlayers`, `maxPlayers`를 함께 저장한다. `minPlayers >= 1`, `maxPlayers >= minPlayers`를 서버에서 검증한다.
- 탐험대는 게임별 최대 인원을 넘을 수 없다.
- 시작 일자 전날 23:59:59 KST까지 최소 인원을 채우지 못하면 자동 취소한다. 이후 탈퇴로 최소 인원 미만이 되어도 즉시 자동 취소한다.

### 이벤트

- 이벤트에는 연결 게임, 시작·종료 시각(KST), 연결된 수량 제한 쿠폰이 필요하다.
- 종료 시각은 시작 시각보다 뒤여야 한다. 기간 종료 후 이벤트 게임은 플레이 목록에서 숨기고 보상을 발급하지 않는다.
- 이벤트 첫 완료 보상은 연결한 수량 제한 쿠폰이다. 같은 플레이어의 두 번째 완료부터는 탐험대 공통 관심사에 연결된 카테고리의 무제한 쿠폰으로 전환한다.
- 수량 제한 쿠폰의 발급 가능 수량이 모두 소진된 뒤에는, 모든 플레이어의 이벤트 완료 보상을 위 무제한 쿠폰으로 전환한다.
- 수량 제한 쿠폰의 발급 수량과 사용 완료 수량은 별도로 저장한다. 만료된 개인 쿠폰도 발급 수량을 복구하지 않는다.

## 보안 및 발행 안전 장치

- 게임/이벤트 생성·수정·발행은 감사 로그에 작업자 ID, 역할, 대상 ID, 작업, 결과, 시각을 남긴다. 감사 로그는 3년 보관 후 삭제하며 수정·삭제할 수 없다.
- 서버는 게임 및 이벤트 발행 요청에 대해 현재 권한, 연결 게임의 발행 상태, 쿠폰의 수량 제한 여부, KST 일정 유효성을 한 트랜잭션에서 검증한다.
- 삭제된 쿠폰, 비활성 제휴업체, 만료 이벤트는 연결 또는 새 보상 후보에서 제외한다.
